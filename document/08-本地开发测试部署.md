# 本地开发、测试与部署

## 1. 推荐本地运行方式

后端默认使用 Go，前端使用 Bun。首次开发建议使用 Docker Compose 提供 PostgreSQL 和 Redis：

~~~bash
docker compose -f docker-compose.dev.yml up -d
cd web
bun install --frozen-lockfile
bun run dev -- --port 5173
~~~

后端源码在容器中运行时，使用：

~~~bash
docker compose -f docker-compose.dev.yml up -d --build new-api
~~~

也可以本地运行后端：

~~~bash
cd web
bun install --frozen-lockfile
bun run build
cd ..
go run .
~~~

生产构建会嵌入 `web/dist`，本地直接 `go run .` 前先构建前端。

## 2. 常用验证命令

根模块：

~~~bash
go test ./...
go build ./...
~~~

独立模块：

~~~bash
cd relaykit
GOWORK=off go build ./...
GOWORK=off go test ./...

cd ../tokenkit
GOWORK=off go build ./...
GOWORK=off go test ./...
~~~

前端：

~~~bash
cd web
bun run typecheck
bun run lint
bun run test
bun run build
~~~

## 3. 按改造类型选择验证范围

| 改动 | 最低验证 |
| --- | --- |
| 纯 Controller/API | 对应 controller/router 测试、`go test ./...` |
| Model/迁移/数据库 | SQLite + MySQL + PostgreSQL 实例，fresh/upgrade/重复启动 |
| Relay 协议 | 对应 handler/channel 测试、流式和错误路径、独立 relaykit 构建 |
| 计费 | 预扣、结算、退款、溢出/边界、日志和任务路径 |
| 认证/会话 | 过期、撤销、重放、权限绕过、Origin/CSRF、限流和审计脱敏 |
| 前端 | typecheck、lint、相关 Vitest、build、i18n |
| Task Plugin | 插件 API 校验、编译/路由冲突、提交/轮询/失败/结算测试 |

## 4. 调试建议

### API 路由不生效

1. 确认 Router 注册函数被 `router/main.go` 调用；
2. 用 Gin route list 或对应路由测试确认方法和路径；
3. 检查路由顺序、通配符和前置中间件；
4. 检查 `FRONTEND_BASE_URL` 是否让请求被重定向到外部前端；
5. 检查认证、限流、Body 限制是否提前 Abort。

### Relay 请求找不到渠道

1. 确认 Token 用户、分组和请求模型；
2. 查看 `model.Channel` 和 `model.Ability`；
3. 查看 `service/channel_select.go` 的约束、优先级和自动分组；
4. 检查渠道状态、模型映射和缓存；
5. 做一次管理台渠道测试，再查看重试和封禁日志。

### 前端页面请求失败

1. 浏览器 Network 查看真实 `/api` 路径和响应；
2. 检查 React Query key 和失效逻辑；
3. 检查后端是否返回 `success: false` 或稳定错误码；
4. 检查会话是否已刷新/撤销；
5. 确认 locale key、权限和空状态没有吞掉错误。

### 异步任务卡住

1. 检查任务是否创建成功，是否有上游任务 ID；
2. 检查 `fetchMode` 和系统任务 Runner 是否启用；
3. 查看 `service/task_polling.go` 的批量/单任务路径；
4. 查看插件或 adaptor 的查询 URL、认证、状态映射和终态判断；
5. 检查任务结算是否在完成或失败路径执行。

## 5. 数据库改造验证

数据库改动不能只跑 SQLite 单测。至少要记录实际验证的：

- SQLite 版本和数据库文件；
- MySQL 版本、连接串和 schema；
- PostgreSQL 版本、连接串和 schema；
- fresh 数据库启动结果；
- 最新版本代表性旧库升级结果；
- 第二次启动/迁移是否幂等；
- 已有数据、索引、约束和唯一性检查结果；
- 日志库路径是否受影响。

## 6. 部署注意点

- 生产环境必须修改 Compose 中的示例密码；
- HTTPS 控制台配置 `SESSION_COOKIE_SECURE=true` 和精确的 `SESSION_COOKIE_TRUSTED_URL`；
- 反向代理必须支持 SSE、长连接和 WebSocket upgrade；
- 持久化 `/data`、数据库、Redis/日志库并做好备份；
- 多节点共享数据库和认证密钥；
- 升级前备份数据库并固定镜像版本，不要盲目依赖 `latest`；
- 通过 `TRUSTED_PROXIES` 明确声明可信代理，避免客户端伪造 IP。

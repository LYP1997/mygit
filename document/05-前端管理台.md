# 前端管理台二开指南

## 1. 前端结构

| 路径 | 作用 |
| --- | --- |
| `web/src/main.tsx` | React 应用启动入口 |
| `web/src/routes/` | TanStack Router 文件路由；页面入口和布局关系在这里 |
| `web/src/features/` | 按业务拆分的页面功能模块 |
| `web/src/components/` | 通用和业务共享组件 |
| `web/src/components/ui/` | 基础 UI 组件 |
| `web/src/lib/` | API、格式化、认证、主题、错误处理等工具 |
| `web/src/stores/` | Zustand 状态 |
| `web/src/hooks/` | React Hooks |
| `web/src/context/` | React Context 和 Provider |
| `web/src/i18n/` | i18next 初始化、语言配置和七套 locale |
| `web/src/styles/` | 全局样式和主题 |
| `web/public/`、`web/assets/` | 静态资源 |
| `web/routeTree.gen.ts` | TanStack Router 生成文件，不要手工维护 |
| `web/package.json` | Bun 脚本、依赖和构建入口 |
| `web/rsbuild.config.ts` | Rsbuild 配置 |

## 2. 新增页面的路径

~~~text
web/src/routes/<route>.tsx
        │
        ├─ 组装页面布局
        └─ 引入 web/src/features/<feature>/...
                    ├─ api.ts：API 请求
                    ├─ components/：页面组件
                    ├─ hooks/：功能 Hooks
                    ├─ lib/：schema、转换和业务工具
                    └─ types.ts：类型
~~~

先搜索已有模块和共享组件，再决定是否新建组件。重点查看：

- `web/src/components/dialog`；
- `web/src/components/confirm-dialog`；
- `web/src/components/copy-button`；
- `web/src/components/data-table`；
- `web/src/components/empty-state`、`loading-state`、`error-state`；
- `web/src/lib/http-client.ts`、`query-client.ts`、`handle-server-error.ts`。

## 3. API 请求和状态

- 查询使用 TanStack Query `useQuery`；
- 修改使用 `useMutation`；
- 请求优先复用统一 HTTP client；
- 成功后按功能失效相关 query；
- 服务端失败要保留稳定错误码/源消息；
- 认证会话变化时清理 Query cache，避免跨用户泄露旧数据。

新增 API 时前后端一起确认：路径、HTTP 方法、请求字段、响应包裹结构、分页结构、错误结构、权限和是否需要刷新缓存。

## 4. 国际化

当前前端语言文件位于：

~~~text
web/src/i18n/locales/en.json
web/src/i18n/locales/zh.json
web/src/i18n/locales/zh-TW.json
web/src/i18n/locales/fr.json
web/src/i18n/locales/ru.json
web/src/i18n/locales/ja.json
web/src/i18n/locales/vi.json
~~~

用户可见文本使用 `useTranslation()` 和 `t('English source key')`。新增 key 后从 `web/` 运行：

~~~bash
bun run i18n:sync
~~~

后端管理台消息通常以英文源文本返回，前端 locale key 必须和后端源文本一致。后端给 AI 客户端、邮件和通知的文本则走根目录 `i18n/`。

## 5. 数字、货币和语言

- 普通数量复用 `@/lib/format`；
- 金额复用 `@/lib/currency`；
- 不要把 `zhCN`、`zhTW` 等界面语言直接传给 `Intl.*`；
- 需要 Intl locale 时先使用 `toIntlLocale`；
- 不要在业务页面复制语言别名映射。

## 6. 前端常见改造场景

### 增加管理台字段

1. 后端 DTO/Model/Controller/API 响应增加字段；
2. 前端 feature 的 `types.ts` 或 API 类型同步；
3. 表单 schema 使用 Zod；
4. 表格、详情、编辑表单分别覆盖；
5. 补齐所有 locale；
6. 检查数字和日期格式、空值、加载、错误和权限隐藏。

### 增加菜单或路由

1. 在 `web/src/routes` 增加页面路由；
2. 查看现有认证布局和 `beforeLoad`；
3. 更新 `web/src/lib/nav-modules.ts` 或对应导航配置；
4. 复用权限和模块可见性判断；
5. 处理移动端、未找到、加载和错误状态。

### 修改认证页面

认证状态集中在 `web/src/lib/auth-session.ts`、`web/src/stores/auth-store` 及相关 `features/auth`。前端只能改善交互，不能代替后端安全控制。

## 7. 前端验证命令

在 `web/` 目录执行：

~~~bash
bun run typecheck
bun run lint
bun run test
bun run build
~~~

只改插件相关前端/JavaScript 时，还要根据项目脚本运行 `lint:plugins` 和格式检查。
